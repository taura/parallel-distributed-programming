# 屋内の受信電力マップをレイトレーシングで作る（下書き）

## 問題

無線通信では、送信機からの電波が壁で遮られたり反射したりするため、
屋内の場所によって受信電力が変わる。部屋の各地点で電波がどの程度届くかを
レイトレーシングで計算し、色のマップとして見えるようにする。

部屋は2次元、送受信アンテナは等方性、周波数は2.4 GHzとする。
直達波と壁での1回だけの鏡面反射を扱う。回折、透過、複数回反射、
アンテナ指向性や材質別の反射係数は扱わない簡易モデルである。

## 逐次版の計算方法

`app.cc` は24 m × 16 mの部屋の外壁と、固定シードで生成した内部の壁を使う。
送信機は部屋の左寄りに置き、受信地点を格子状に動かす。直線が壁に遮られなければ
直達経路を採用する。反射経路は、送信機を壁の向こう側に鏡映する「鏡像法」で
求める。反射点が壁の線分上にあり、往路と復路が他の壁に遮られないときだけ採用する。

経路長 $d_p$、周波数 $f$、光速 $c$、波長 $\lambda$ を使い、
直達波と反射波の複素振幅を足して受信電力比を求める。

$$\frac{P_r}{P_t}=\left|\sum_p \gamma_p\frac{\lambda}{4\pi d_p}
\exp\left(-j2\pi f\frac{d_p}{c}\right)\right|^2$$

直達波は $\gamma_p=1$、反射波は一律 $\gamma_p=-0.65$ とする。
送信機のごく近くでは発散を避けるため経路長を最小0.05 mに制限する。
出力のPPM画像では青が弱い電力（-100 dB以下）、赤が強い電力（-40 dB以上）、
白線は壁、黒い十字は送信機の位置を表す。
計算時間、見通し地点の割合、平均受信電力比、電力範囲も表示する。

実行例（Miyabi上で `code/` に移動後）:

```sh
clang++ -O3 -Wall -std=c++17 app.cc -o app
./app 384 256 32 1 1 coverage.ppm
```

引数は順に画像の横・縦の画素数、内部壁の数、乱数シード、反射の有無（0/1）、
出力先。実行時間が短ければ `./app 1024 768 96 1 1 coverage.ppm` のように
規模を上げる。表示される `compute_seconds` を見てMiyabiで調整する。
`./app 64 48 0 1 0 free_space.ppm` は内部壁・反射なしの検証用。
すべての地点が見通しになり、距離に応じた自由空間の式
$(\lambda/(4\pi d))^2$ とほぼ一致する。
プログラムの実行後、`code/` 内で `convert coverage.ppm coverage.png` とすれば、
ノートブックから `display(Image("code/coverage.png"))` で画像を表示できる。

## 並列化できる部分

各受信地点の計算は独立なので、CPUでは画像の行や領域を分担でき、
GPUでは多数の画素を同時に計算できる。壁との交差判定や三角関数が
計算時間を占める可能性があり、地点によって有効な反射経路の数が違うことが
負荷の偏りになりそうである。
